# Editor: per-frame text layout and texture caching

After phase 6 is fine, except point 2 (a small, real bug, fix whenever).

1. **Text is laid out several times per element per frame.** `Element::bounds`/`frame`/`hit`/`key_points` (image/src/geom.rs:174-259) each call `Fonts::layout`. The move tool calls them for every element on every frame the pointer moves (`hit_test`, editor/src/canvas.rs:15). Painting calls them again (`element_prims`, key points, `key_cursor`), so each text is laid out about 4–6 times a frame. Layout itself is quadratic in line length: `wrap` reshapes the whole candidate line for every word (text.rs:120-150). `advance` builds a skrifa `GlyphMetrics` per glyph (text.rs:73). Measure first (an image with ~20 multi-line texts while moving the pointer). Likely fixes: build `GlyphMetrics` once per (face, size) in `shape`, measure the wrap incrementally, and keep a small LRU in `Fonts` keyed by `(text, size bits, width bits)` (a `Mutex`, since `Fonts` is shared across threads by the server).
2. **SVG texture thrash.** `Textures::svgs` is keyed by `AssetId` alone and keeps one size step (paint.rs:440, 468-487). Two instances of the same SVG on screen at different sizes (insert cascades the same asset; resize one) ask for different steps every frame. Each frame then re-renders the SVG on the CPU and re-uploads it, twice. Key by `(AssetId, step)`.
3. **Raster textures.** Each raster is uploaded once per filter, `(AssetId, nearest)` (paint.rs:453). Zooming past 2 device px per canvas px uploads a second full copy (a 4K screenshot is 33 MB, plus mipmaps), and both stay alive for 300 frames. Rasters can be up to 16384 px per side (`MAX_SIDE`), more than many GPUs' max texture size, and nothing checks egui's `max_texture_side`. Upload once and sample nearest/linear per draw if egui allows it, or drop the other entry immediately. Over `max_texture_side`, upload a downscaled copy (the CPU renderer stays exact).
4. **Font atlas churn while zooming.** Text is drawn with egui galleys at `size * zoom` (paint.rs:413, text.rs:183), so every zoom step during a pinch or wheel zoom rasterizes the glyphs at a new size into egui's shared font atlas. A long zoom fills the atlas and triggers egui's full font rebuild, which costs all UI text too. Quantize the on-screen font size (e.g. 1/16 octave steps) and scale the galley's mesh by the remaining factor, or paint text from core's glyph outlines (already used by the CPU renderer) as egui meshes.
