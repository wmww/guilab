# Editor output: what lands in the Doc should be clean, valid and reachable

**Land before phase 6** (point 1 is a regression phase 6 would ship; the rest are cheap to do at the same time). Everything the editor commits becomes what agents read in listings, and has to pass `Body::check` at send.

1. **Fractional coordinates in listings.** The editor commits raw float canvas coordinates: `xf.invert` of pointer positions (canvas.rs:310, 382, 472), moves by fractional deltas, and `fit_to` results. The listing prints one decimal (`format::num`), so agents see `blue box 260.4,180.7 519.8x90.2`. Copying a line back also changes the element slightly. Today's path rounds to whole pixels when the server converts markup marks (`server/src/viewer.rs` `element`). Phase 6 deletes that and freezes drafts as they are, so listings get noisier. Fix: snap committed geometry to whole canvas px at commit (draw release, move/reshape release, text placement), and drop consecutive duplicate pen points after snapping. Snap in the editor, not in core, so `image make` keeps exact values.
2. **Pen strokes have no point budget.** A point is pushed for every pointer move of at least 1 screen pt (`PEN_STEP`, canvas.rs:482), so a long scribble while zoomed in makes thousands of points. `MAX_PEN_POINTS` (100k per body) and `MAX_ELEMENTS` are checked only when the draft is frozen (`Store::add_image` → `Body::check`). The human finds out at send, with no way to fix it. Simplify the stroke at release (Ramer–Douglas–Peucker at ~0.5 canvas px). Also refuse to commit a mark that would break a `Body` limit: show a toast, or just don't add it. A `Doc::can_add(&Element)` that checks the limits keeps the rule in core.
3. **Elements can be dragged out of reach.** Drawing clamps to the view region (canvas.rs:474), but Move doesn't (canvas.rs:496). Hit tests only look inside the region (`hit_test`, canvas.rs:19/34), and key points outside it are hidden. So an element dropped fully outside the crop or canvas can't be grabbed again, and only undo brings it back. It still shows in the listing. Clamp the move delta so the element's bounds keep overlapping the region by a few screen points (same for reshape).
4. **Zero/NaN zoom.** See `editor-canvas-input.md` (Xf::fit clamp). It belongs here too because NaN points are what fail `Body::check`.
