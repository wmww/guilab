# Code map

## Crates (`crates/`)
- `proto` (`guilab-proto`): control protocol types (`Request`, `Command` = `Global(GlobalCmd)` | `Session(SessionCmd)` (one `cmd`-tagged object on the wire; a custom `Deserialize` keeps serde's specific errors), `Response` + reply structs, `PROTO`). `SessionCmd::policy()` is the one table of how the server treats a command (lock `Access`, `delivers`, `needs_working`, `human`); exhaustive, so a new command must decide each. `check_output` = output size/scale limits (`new`, `output`, viewer resizes), socket paths (`runtime_dir`: `$GUILAB_DIR` or `$XDG_RUNTIME_DIR/guilab`), blocking `Client`. `input.rs`: the `input` grammar (`Action`, `Action::check` = value limits (`MAX_MS`, ...), enforced by the server via `check_chain` and by `parse`, `parse`, `Display`, and `HELP`, which is `guilab input --help`). Event log, pure logic so it's unit-tested cheaply here: `events.rs` (`Event`/`EventData`; `KINDS` = the one table of kind names and default tiers, read by `default_tier`, `expand_kinds` and `poll --help` (unit test `kinds_table` forces every variant into it); `GROUPS`; `Tiers` overrides resolved once per request into `ResolvedTiers`; `Delivery`), `log.rs` (`EventLog`: append, motion/scroll coalescing, per-key delivery cursors, the unread mark for human messages, `query`), `text.rs` (`Fmt`: all event text, human input run summaries, `clock`/`file_stamp`; `local_offset()`/`Fmt::local()` = the one local-time source for CLI and server). `SessionCmd::log_text` = how a command appears in the log. serde only, has the cheap unit tests.
- `compositor` (`guilab-compositor`): smithay. `Session` = one Wayland display. No IPC, no CLI.
  - `session.rs`: `Session` struct, globals, socket, seat, output. `Session::new` returns the session plus its own `EventLoop<Session>`. Fields are `pub(crate)` except what the server reads (`name`, `tag`, `dir`, `frame`, `frame_seq`, `clip`, and `log`, which it also writes); state with an invariant lives in sub-structs (`settle::Times`, `Clipboard`, `InputState`, `CursorState`). The server uses `touch()` (render next tick), `note(text)` (overlay note), `viz()`. Scale: `scale()`, `to_px`, `from_px`. `impl Drop for Session` (procs.rs) kills the bus and tracked children if `shutdown()` didn't take them (e.g. `new` failing after the bus started); `spawn` kills a child it couldn't watch.
  - `handlers.rs`: all smithay handler traits except xdg-shell and X11, `delegate_dispatch2!`, surface ids (`SurfaceId` in each surface's data map, assigned in `new_surface`), dmabuf blocker pre-commit hook, `SelData` (owner of a compositor-side selection: `clip set` text or an X client).
  - `shell.rs`: xdg-shell + decoration. Window policy (`should_tile`, shared with X), focus and stacking for Wayland and X windows (`focus_window`, `parent_window`, `move_window`); every toplevel configure goes through `Session::configure` (notes it for settle), popups (anvil's unconstrain + grab), `relayout` after output changes.
  - `xwayland.rs`: per-session Xwayland + `XwmHandler` (from anvil's `shell/x11.rs`): spawn on our display range, X window policy (`x_place`), override-redirect stacking (`xw.or`), clipboard/primary bridging.
  - `grabs.rs`: `MoveGrab`, the pointer grab for interactive window moves.
  - `xscale.rs`: our own x11rb connection to the session's X server (`XConn`): HiDPI for X clients (`x_apply_scale`: client scale, XSETTINGS, Xft.dpi, root cursor; on ready and on scale change) and pids via X-Resource for windows without `_NET_WM_PID`.
  - `focus.rs`: `KbFocus` (keyboard focus: `WlSurface` or `X11Surface`; the X arm does SetInputFocus/WM_TAKE_FOCUS). Pointer/touch focus stay `WlSurface` (smithay's X11Surface targets only forward to it; X menus grab inside Xwayland).
  - `cursor.rs`: the apps' cursor (`CursorState`; `AppCursor`: named, hidden, or a rendered cursor surface), theme cursors, drawing it into `screenshot --cursor`.
  - `frame.rs`: `tick()` (render, presentation feedback, frame callbacks), PNG writing, `set_output`.
  - `settle.rs`: `Times` (commit/render/configure/input/spawn/map, each noted from one place), `settle_state`, and `shot_ready` (the whole screenshot wait decision, caps included).
  - `render.rs`: `Gpu` (GLES on a render node, pixman fallback; `GUILAB_RENDERER=pixman|/dev/dri/renderD*`), per-session offscreen `Frame` with a damage tracker, `render_surface` (a surface tree to RGBA, for cursors), `software_gles` (llvmpipe, the viewer's renderer on pixman servers).
  - `tree.rs`: `tree` reply; `track_windows` (each tick) diffs toplevels to log window open/close/title. `procs.rs`: run/kill/ps and cleanup; logs app exits (`reap`).
  - `Session::log` (`EventLog`) holds the session's events; the compositor logs human input, windows, app exits; the server logs the rest.
  - `input.rs`: `InputEvent` + `Session::inject(ev, InputSource)`, the only path from any input to the seat; logs `Human` input (output pixels, keysym name + typed char, window under the pointer). Hit-testing, click-to-focus, `InputState` (held buttons/touches/open gesture in `Held`, key repeat, extra keys, popup-click and X-focus timing; `release_all` releases them and keys, cancelling a gesture), popup-grab workarounds.
  - `actions.rs`: input chains (`Chain::new(actions, source)`: agent `input`, or the human's via `guilab debug input`): proto `Action`s -> events. `run_chain` returns `Some(delay)` at sleeps/glide steps; the server resumes it. Output pixels -> logical here.
  - `keys.rs`: keysym lookup over the seat keymap (key + Shift/AltGr), key name aliases, and the extended keymap for typing characters the keymap lacks.
  - `clipboard.rs`: `Clipboard` (owner mimes + `seq`, changed only via `set_owner`, which bumps the seq the viewer bridge watches), `clip set` (server-owned selection, written from a thread, announced to the X11Wm) and `clip get` (own text, or a pipe from the owning Wayland client or X11Wm).
- `server` (`guilab-server`): the daemon. Outer calloop loop: control socket, connections, a 16 ms timer, signals, each session's nested loop. `requests.rs`: request dispatch (`handle` sends every reply; `handle_session` returns `Reply::Now | Later(Wait) | Then(Response, Wait)`), session resolution, lock check, logging commands and their events, `new`. Every reply to a session command goes through `Server::attach` (adds the client's undelivered events and the unread count; key = worktree root or anonymous). `pending.rs`: requests answered later, one `Vec<Pending>` (`Wait::Shot | Input | Clip | Kill | New | Poll`) stepped from the tick (`step_pending`; input chains also right when queued). Shared rules there: a client that hung up drops its request (an input chain that already ran `release_all`s, like an unlock), replies carry deliveries except polls (they deliver with their own tiers), `end_pending` answers all of an ended session's, input chains run one per session in order. Polls: `read_messages` marks the agent working when a poll shows a message. `out.rs`: `Outbox`, all writes to clients: non-blocking; what doesn't fit is kept per socket (by inode, so clones stay in order) and flushed each tick; a client with 8 MB unsent or 30 s without progress is shut down. The viewer's `show` waiters live in `ViewerState` (tied to its lifecycle). `handle_line` checks the request's `proto` before parsing it. `images.rs`: `Images` (the server-wide `Store`, one `Group` per session in `Slot::group`, dropped at session end; swept once a second): `capture` (the one `Raster::from_capture` caller; reuses the last raster while `frame_seq` and size are unchanged and no cursor), `render_file` (`img/<id>[-c..][-m..][-nomarks].png`, named from `guilab_image::layout` and reused without rendering, since images never change), `make`, `attach` (id or absolute file path → image), `drawing` (viewer marks on the frozen base), `image_ref` (listing snapshot + marks bbox for events). `lock.rs`: `LockState`, pure token logic (`take` → `Took`, `may_release` (no change, so callers do fallible work first) + `release`, `check`, `revoke`, `is_locked`). `slot.rs`: `Slot` (session + agent state: lock, `working`, `last_agent`, TTL, image group) and every agent transition: `set_working`/`set_done`, and `Server::end_lock(name, LockEnd, key)`, the one path after a lock ended (Unlock/Done/Revoke/TakenOver: logs the event, `release_all(Agent)`, aborts the session's input chains). `revoke_lock` = the human's Stop.
- `guilab`: the binary. `main.rs` (clap CLI; hidden `debug` = the human's actions; hidden `say` = an error pointing to work/done; `poll_help()` built from `KINDS`/`GROUPS`), `client.rs` (connect + autostart unless `GUILAB_NO_AUTOSTART`, protocol/build check, `server`, `server --wait`/`--stop`), `build_id.rs` (GNU build id via `dl_iterate_phdr`), `format.rs` (text output; delivered events and the unread notice go to stderr, poll output to stdout). Integration tests in `tests/it/` (one test binary).
- `viewer` (`guilab-viewer`): the viewer window, see `viewer.md`. Generic part (no guilab types; an egui host for any smithay program): `source.rs` (calloop source for the host connection whose errors stay local), `host.rs` (sctk window, dmabuf/shm presentation with a dmabuf probe, host input → ordered `HostInput` incl. touch, cursors (`HostCursor`: shape or image), `WindowOp`s for client-side decorations), `clipboard.rs` (host text clipboard), `gfx.rs` (egui_glow painter on smithay's GL context, mirror textures, CPU frame textures). guilab part: `ui.rs` (`ViewerUi`: tabs, session view with zoom/pan/input forwarding, lock bar, and per session (`PerSession`, keyed by name, reset when the session key changes) a `Sketch` + `Chat` from markup in a left and a bottom panel; View menu `Prefs` (theme, chat place; the server keeps them in `Server::viewer_prefs` across hide/show); `SessionView` in, `Action` out: input, revoke, `Freeze` (a drawing wants a screenshot), `Message`, `Resize`), `sizing.rs` (resize to/lock to window, resize handles), `viz.rs` (input overlay), `portal.rs` (desktop light/dark from the XDG settings portal on the server's own session bus: a ~250-line blocking D-Bus client on a thread, no D-Bus crate; `color_scheme()` → `RawInput::system_theme`) and `lib.rs` (`Viewer`: draw scheduling, key routing, `feed_next`/`push_feed`/`set_screenshot`). Depends on smithay, markup and kit, not on the compositor or server.
- `kit` (`guilab-kit`): the egui toolkit, egui only, no guilab types. `theme.rs` (`Theme` tokens: colors, space, size, radius, font, motion, overlay; `dark()`/`light()`; `install(ctx)` stores both and sets egui's styles from them, egui picks the variant via `ctx.set_theme` / `RawInput::system_theme`, fallback dark; `ThemePref` System/Light/Dark), `anim.rs` (`Easing`, `Motion`, `tween`, `progress`, `lerp_rect`), `history.rs` (`History<Op>`: groups, limit 500, `retain`), `menu.rs` (the menu bar, see `viewer.md`), `widgets.rs` (toast, tool_button, swatch, send_button, close_badge, tab, thumb_frame, preview, field_frame, window_button, pointer_label, `flat_fill`, `consume_plain_enter`). Widgets read `Theme::get(ctx)`; nothing hardcodes colors or sizes. `headless.rs` (`Headless`: frames from synthetic events (`ev::*`), CPU paint of the output incl. user textures and mips, for tests and screenshots). Unit tests (`tests.rs`, bare `egui::Context`): menu mouse and keys, theme switching.
- `markup` (`guilab-markup`): drawing on screenshots, the queue and the chat panel as plain egui widgets; depends only on egui and kit. `mark.rs` (tools, palette, `Mark` -> egui shapes through an `Xf`), `raster.rs` (`Renderer`: CPU composite by tessellating those shapes with epaint and rasterizing the triangles, font atlas included; `downscale`), `sketch.rs` (`Sketch`: toolbar, `canvas(ui, View)` over the host's image rect, text editing, queue strip, `take_all` -> `Annotated { image, preview, notes, tag, marks, scale }`; the server rebuilds drawings from `tag` (the base image id) + `marks`, ignoring the composites), `chat.rs` (`Chat`: feed of `FeedItem`s + the agent's `Status` line + message box -> `Outgoing`). Unit tests (`tests.rs`) drive it with a bare `egui::Context`; `examples/compose.rs` composites marks onto a PNG standalone (handy for making annotated samples).

## Runtime layout
`$XDG_RUNTIME_DIR/guilab/` (or `$GUILAB_DIR`): `control.sock`, `server.lock` (flock: one server per runtime dir), `server.log` (autostarted server's stderr), `s/<session>/` = the session dir: `wayland-0` socket, `bus` + `bus.conf` (private D-Bus), `app-N.log`, `xwayland.log`, renderings `img/<id>[-c..][-m..][-nomarks].png` (screenshots, `image`, `image make` previews; all carry the `guilab-render` PNG mark). Xwayland uses the machine-wide `/tmp/.X11-unix/X<n>` + `/tmp/.X<n>-lock` (n from 100; smithay writes our pid in the lock and reclaims locks of dead pids, so a crashed server's leftovers get reused) plus the abstract socket. The session dir is the apps' `XDG_RUNTIME_DIR`, so apps don't see the user's bus (they get the session's own), pipewire or compositor. It's deleted when the session ends. Socket paths must stay under 108 bytes, hence session names are capped at 32 chars and tests use `$XDG_RUNTIME_DIR/glt-*` rather than the scratchpad.

## Event loops
- Server loop data is `Server`. The viewer's host connection (`HostSource`) and the connect-result channel are sources in the server loop. Each session's `EventLoop<Session>` is inserted as a `Generic` source (an EventLoop is `AsFd`); on readiness the server dispatches it with `&mut slot.session`, then flushes clients. The session's display, socket, pidfds and dmabuf blockers are sources in the session loop.
- **Never put a calloop `Timer` in a session loop**: calloop timers live in the poll timeout, not in an fd, so they never wake the server loop. Timed work goes through the server's 16 ms tick (`Server::tick`: session `tick()`, `reap_tick()`, pending requests, viewer, outbox flush, graveyard, TTL/idle once a second).
- No source closure in a session loop may capture its `LoopHandle` (Rc cycle, the session would leak). Use `s.handle` from the `&mut Session` argument.
- smithay APIs taking `LoopHandle<'static, D>` (e.g. `X11Wm::start_wm`) get `session.handle`.

## Behaviours worth knowing
- Settle (`settle.rs`): a toplevel has a buffer, no configured-but-unmapped toplevel, no unanswered configure (not acked, or acked but not yet committed: GTK acks a scale change and commits ~20 ms later; ignored once `CONFIGURE_WAIT` = 1 s passed since we last configured, because clients may ack without committing, e.g. weston-flower), the app from the last `run` has mapped a toplevel (or exited, or `NEW_APP_WAIT` = 10 s passed; `Settle::Starting`, capped like no window at all), 150 ms without commits or input, and a render after the last commit. **Animating**: commits with no 150 ms gap for `ANIM_DETECT` = 1 s (spinners, video) count as an animation; then the shot is taken once input is `ANIM_REACT` = 300 ms old, reported as `animating` (session-wide, not per surface: GTK draws a whole window as one surface anyway). `shot_ready` caps waits at 3 s (10 s while waiting for a window: the first, or the last `run` app's). Screenshots also report toplevels sticking out of the output (`cropped`, 1 px slack).
- Idle sessions don't render: `Session::dirty` is set by commits, any dispatch of the session loop (client requests, e.g. a popup destroyed), every control command on the session (`touch()`), and `inject`; `tick` renders only when dirty (or a DnD icon follows the pointer). Frame callbacks, `space.refresh`, popup cleanup and window tracking still run every tick. Four idle GTK sessions cost well under 1% of a core.
- Apps get their own process group and `GUILAB_TAG=<tag>`. Kill = SIGTERM to the group, SIGKILL after 2 s. Ending a session also signals every process carrying the tag (`/proc/*/environ` scan), like guibox. Apps die with the server via PDEATHSIG.
- The server blocks SIGTERM/SIGINT/SIGHUP (calloop signalfd) and ignores SIGPIPE; `std::process::Command` doesn't reset either, so `spawn` clears the mask in `pre_exec`. Without that, apps ignore SIGTERM.
- At fractional scales a tiled window can be one pixel larger than the output (500 px / 1.5 = 333.3 logical, rounded up to 334). `tree` reports it honestly.
- `tree` lists toplevels topmost first, coordinates in output pixels (edges rounded half-down). Popups appear once they have a buffer (before that their geometry can be 0x0; clicking "the middle" of one hit its edge under load), and settle counts a popup without a buffer as still drawing.
- Keys wait `X_FOCUS_WAIT` (100 ms) after keyboard focus moved to an X window: SetInputFocus (our X11 connection) and the keys (Wayland) reach Xwayland on different sockets, and keys that won the race went to the old X focus.
- Window policy: a parentless toplevel tiles if no other tiled one exists; otherwise it floats, centered plus `WindowState::offset` (set by `cascade` at first map, changed by moves: `grabs.rs` `MoveGrab` → `drag_window`), clamped on screen (`clamp_on`), with `bounds` = output (so an oversized default size fills the output anyway). X floats use the same offset in `x_rect`.
- Popups are positioned by smithay's positioner (flip/slide/resize) against the output, relative to their parent window.
- Stacking: floating windows always above tiled, dialogs above their parents (`focus_window`), X override-redirect windows above all (re-raised in X order after every restack). Click/touch-down focuses and raises, unless a grab is active; override-redirect windows never take focus. `Space::map_element` always raises, so moving a window goes through `move_window`.
- X window sizing before map: smithay maps the client window into its frame before calling `map_window_request`, so the app sees MapNotify before our placement. Hence a ConfigureRequest from a not-yet-mapped window that will tile (`x_would_tile`) is answered with the output size: apps lay out once, at their final size.
- X windows live in the same `Space<Window>` (`Window::new_x11_window`), so rendering, hit-testing, `on ID` and screenshots need nothing special. Space position = X position (`configure_notify` keeps them in sync), which X menus rely on. X surfaces get a new wl_surface (and so a new `tree` id) on every map; the xid stays. Settle counts mapped X windows: one without a buffer yet is "drawing".
- Xwayland lifetime: it lives in the session loop as the `XWayland` source; dropping the loop (session end) removes lock and sockets and closes its Wayland connection, which makes it exit. It carries the session tag. If it dies, `XwmHandler::disconnected` drops X windows and the session stays up without X.
- Settle treats delivered input like a commit (`last_input`), so a screenshot right after `input` waits for the app to react.
- Popup grabs (smithay, spec-conformant): clicks on the popup client's own surfaces don't dismiss; the client closes its menu itself. smithay quirks worked around in `input.rs`: an ended popup pointer grab swallows the next motion (we resend it); the popup keyboard grab keeps focus on the dead popup until the next key (`popup_may_close` hands focus back; chains wait up to 500 ms before keys after a click while a menu is open, or the keys go to the closing menu).
- Typing: characters on the keymap use their real keys (+Shift/AltGr), but only keycodes <= 255 (X can't see higher ones; `us` has EuroSign only on 443). Others: the seat keymap is swapped for one with them on spare keycodes <= 255 (16 in `us`, two characters per key: plain and Shift, `keys::Extra`), sent to all clients of the session. X clients look keys up in whatever keymap they fetch when they get to the keys (Xlib refetches lazily, after MappingNotify, possibly several swaps later on a busy machine), so: the extended keymap stays active afterwards (its other keys are the base keys); a swap keeps every key typed since the previous swap as it was and places new characters on the other spare keys; and with an X window focused a swap first waits until the session settles (the app drew the keys so far; at most 2 s). Replaces smithay's `inject_text_keysyms` (its codes start at 9 = Esc for raw-keycode clients).
- Clipboard to X: `X11Wm::new_selection` only queues SetSelectionOwner on its connection (no flush), so `announce_selection` does a round trip after it; otherwise X clients pasting right after `clip set` still see the old owner. Our own text sent as X `STRING` is Latin-1 (`?` for the rest).
- Input chain sleeps resume from their scheduled time, not from the tick that ran them (else 16.7 ms glide steps took two 16 ms ticks each and glides ran at half speed).
- Lock tokens: 8 chars from `/dev/urandom`. Every lock end (unlock, done, revoke, takeover) releases held input and aborts the session's queued input chains with an error (`Server::end_lock`). Commands with side effects do all fallible work (token check, image attach) before changing anything.
- Edition 2024 `if let` keeps temporaries alive through the block: `if let Some(w) = self.space.elements().find(..).cloned() { self.space.map_element(..) }` fails to borrow-check; bind the result first.

## Build and test
- smithay is git master pinned in the root `Cargo.toml` (crates.io 0.7 lacks `delegate_dispatch2!`, `inject_text_keysyms`, etc.). Bump the rev deliberately.
- Only `cargo test --workspace` (narrow with `--test it <module>::` or a name filter) and `cargo clippy --workspace --all-targets`. No `-p`, no feature flags, no per-command env (each combination builds another copy of the tree). Dev profile only; deps at opt-level 2, line-tables debuginfo, compressed debug sections (`.cargo/config.toml`).
- compositor, server and viewer libs have `test = false`: each lib test binary would link all of smithay. Prefer integration tests in `crates/guilab/tests/it/`, or unit tests in `proto`, `kit` and `markup` (egui only) and `image` (no smithay; cheap).
- `images.rs` tests screenshots as images, rendering, `image make`, attaching files. `events.rs` tests use `guilab debug` for the human side and need no app except `window_events` (GTK4). Integration tests start a private server per test (`Lab`, runtime dir `$XDG_RUNTIME_DIR/glt-<pid>-<n>`) and skip tests whose apps aren't installed. Xwayland tests (`xwayland.rs`) skip without Xwayland or tkinter. Test apps: `tests/it/apps/tk_app.py` (Tk, pure X11: entry, a menu button posting an override-redirect menu, a transient dialog), `gtk_app.py` (PyGObject GTK4: `--menu` popover in the bottom-right corner, `--dialog`, `--second`), `gtk_cursors.py` (named / image / hidden cursor areas), `gtk_input.py` (entry, button, double-click/context-menu area, scroll list, DnD, zoom gesture; `--floats`), `qt_app.py` (PySide6: line edit, right-click QMenu, `--menu`). The input apps print each event and their widget positions (`pos NAME X Y W H`) to their log; tests read it (`wait_log`, `center`).
- Test harness (`tests/it/harness.rs`, its module doc says how to wait): `Lab` and one CLI runner (`exec_with`, wrappers `run`/`json`/`try_run`/`status`), `wait_until(what, secs, || Ok/Err(state))` under every wait (`wait_log`, `wait_tree`, `wait_clip`, `wait_polls`, `wait_dead`; 30 ms polls, timeouts at least 15 s since they only matter when broken; `#[track_caller]`, so failures name the test line), app detection (`have`, `gtk4`, `qt6`, `xwayland`; `GUILAB_REQUIRE_APPS=1` turns skips into failures). Never sleep-then-assert: wait for the observable thing. For things only the server knows, `ping` (`Lab::info`) reports `pending` request counts (polls, inputs, screenshots, clips) and, for the viewer, its host `window` size and `dropped` (human presses/keys/touches the lock stopped). A negative check ("this click must not arrive") needs a later event that's processed after it (see `click_through`).
- Flaky tests: reproduce under load, never by retrying alone: run several copies of the `it` binary at once (`target/debug/deps/it-*`, each test has its own server) in a loop, plus busy-loop processes for a build's worth of CPU (24 here). Fixtures shared by parallel tests must be written atomically (the image tests' `put`).
- Numbers (24-core machine): clean build ~75 s; no-op 0.05 s; one-line edit in compositor or server + test build ~0.6 s; `cargo test --workspace` runs in ~7 s (tests run in parallel; the slowest are the GTK input and viewer ones); `target/` ~2.7 GB. 3x worse at low load means something's wrong.
- Forcing toolkits onto X in a `-x` session: `GDK_BACKEND=x11`, `QT_QPA_PLATFORM=xcb` (we set `wayland` only if unset), `chromium --ozone-platform=x11`.
- `viewer.rs` tests need GLES (skip otherwise) and use a second server as the viewer's host. `GUILAB_VIEWER_SHM=1` in the server's environment forces the shm path.
- Manual testing: the CLI against the real runtime dir works fine; `guilab server --stop` after rebuilding (the CLI warns when the server runs another build). For a private server, `GUILAB_DIR=$XDG_RUNTIME_DIR/glv-x` (keep it short: socket paths). `GUILAB_LOG=warn,guilab_compositor=trace guilab server` runs a foreground server with commit tracing.
